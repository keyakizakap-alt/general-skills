# Anti-AI Design

**AIっぽさとは、センスの欠如ではなく「決めなかった箇所がデフォルトで埋まった状態」のこと。**

生成モデルは訓練データの中央値を出す。制約を与えずに「LPを作って」と言えば、2019〜2024年のTailwindチュートリアルの平均が返ってくる。
だから対策は「おしゃれにする」ではなく、**実装を始める前に決定を固定すること**。

---

## 実行手順

### Step 0. 設計ブリーフを3行で確定する（実装前に必ず）

依頼文から次を確定する。書かれていなければ**推論して明示**する（質問で止めない）。

| 項目 | 内容 | 不明時の既定 |
|---|---|---|
| `参照点` | 「〜のような」で挙げられる具体例（実在サービス、業界の定番、紙媒体でも可） | プロダクトの業種から最も近い実例を1つ選び、前提に明記 |
| `質感` | 形容詞1語（硬質 / 温かい / 事務的 / 高級 / 素朴 / 無骨 など） | 用途から推定（業務システム→事務的、個人向け→温かい） |
| `主役` | 画面で最も目立つべき1要素（数字 / 写真 / 文章 / 操作 / 図） | 主要ユースケースから決定 |

詳しくは `assets/design-brief.md`。ブリーフが埋まらないまま実装に入ると、必ず中央値に落ちる。

### Step 1. 5つの決定を先に固定する

コードを1行も書く前に、この5つを言語化して宣言する。`references/decisions.md` に決め方と具体値。

1. **色** — 基準色を1つ決める（**indigo / violet / purple は既定では選ばない**）。使う色数は「基準色 + 中立色2〜3段 + 警告色」まで。グラデーションは原則使わない
2. **文字** — 見出しと本文の組み合わせを明示的に選ぶ（Inter単独は既定なので選ばない）。日本語なら和文フォントを先に決める
3. **余白** — 基準値を1つ決め、その倍数だけを使う（4px基準なら 8/12/16/24/32/48）。余白は「詰める」のではなく**差をつける**
4. **形** — 角丸・枠線・影のどれで要素を区切るかを**1つだけ**選ぶ。3つ全部使うとAI的になる
5. **主役** — 画面に1つだけ「他と明確に違う扱い」の要素を置く。全部が同じ重みだとテンプレに見える

### Step 2. 実装する

`references/stacks.md` に、Tailwind / 素のCSS / shadcn/ui など環境別の「デフォルトから抜ける」具体手順。要点だけ:

- **デフォルト値を使わない**。Tailwind なら既定パレットを上書きし、独自トークンを定義してから書く
- **中央寄せの連続を避ける**。ヒーローもセクションも全部中央揃えは最も強い兆候
- **同じカードを3枚並べない**。並べるなら重みを変えるか、別のレイアウト（表・リスト・図）を検討する
- **アイコンは絵文字を使わない**。用意できないなら文字か記号で代替する
- **実データを入れる**。ダミーテキストのまま整えると、必ず均質な見た目になる

### Step 3. 兆候を検査する

```bash
python3 scripts/check_ui.py <ファイルまたはディレクトリ>
python3 scripts/check_ui.py src/ --strict     # 弱い兆候も不合格にする
```

検出された項目は `references/tells.md` の代替案に置き換える。
コード実行が使えない環境では、`references/tells.md` の一覧を目視で当てる。

## 最頻出の5兆候（これだけでも潰す）

| 兆候 | なぜ出るか | 代わりに |
|---|---|---|
| 紫〜青のグラデーション | Tailwind の既定色が indigo-500 で、訓練データ中の出現数が突出している | 単色の背景 + 基準色のアクセント。グラデーションを使うなら同系色の微差に留める |
| Inter（または既定サンセリフ）1本 | 無指定時の定番 | 見出しと本文で別の書体を選ぶ。日本語なら和文を先に決める |
| 角丸カード3枚 + 小アイコン + 2行テキスト | 「特徴を3つ」の最頻出レイアウト | 数を変える、重みを変える、表や図に置き換える |
| 絵文字アイコン（🚀 ✨ 🎯） | アイコン素材がないときの穴埋め | 記号・番号・図版。なければアイコンなしで成立させる |
| 「〜を、もっと自由に」「次世代の〜」 | コピーの中央値 | 主語と数字を入れた具体文にする（誰が、何を、どれだけ） |

---

## 「AIっぽい」と言われたときの直し方

作り直す前に、**どこが中央値なのかを特定する**。

1. `scripts/check_ui.py` で機械的な兆候を洗う
2. Step 1 の5決定のうち、**明示的に決めていない項目**を特定する（たいてい原因はここ）
3. 最も影響が大きい1つ（多くの場合は色か余白）から直し、他は触らない
4. 全面作り直しは最後の手段。1箇所ずつ直したほうが、何が効いたか分かる
