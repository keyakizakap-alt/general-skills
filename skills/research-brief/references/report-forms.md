# 調査メモの型（種類別）

どの型も、冒頭に「想定した範囲」の1行、末尾に「出典」を置く。長さは目安で、指定があればそちらに従う。

## 短い調べもの

1つの事実を確かめる依頼（「この機能はもう一般提供？」「上限はいくつ？」）。

- 構成: 答え（1〜2文、出典番号つき）→ 条件や例外（あれば）→ 出典
- 長さ: 200字以内
- 省いてよいもの: 差分、影響、活用案

## 仕様・提供状況の確認

提案や設計の前提を固めるための確認。

- 構成: 結論 → 確認した項目の表（項目 / 現在の値 / 条件 / 出典番号）→ 未確認 → 出典
- 表に入れる項目: ステータス、提供地域、料金の単位、上限、前提条件、廃止予定
- 落とし穴: 発表記事だけで確かめ、ドキュメントの現在の記述を見ていない

## 動向のまとめ

一定期間に何が起きたかを知りたい依頼。

- 構成: 結論（この期間でいちばん大きな変化を1つ）→ 何が変わったか（時系列ではなく、影響の大きい順）→ 業務・活動への影響 → 活用案 → 推測・未確認 → 出典
- 各項目に「以前はどうだったか」を書く。差分が書けない項目は、新しい情報ではない
- 対象期間を明記し、期間外の出来事は背景として1〜2行にとどめる
- 活用案は、相手の仕事で今週試せる大きさのものを1つ以上入れる
- 落とし穴: 発表を並べるだけで、相手に何の関係があるかが無い

## 比較調査

複数の製品・手段を同じ軸で比べる依頼。

- 構成: 結論（どの条件でどれが向くか）→ 比較表 → 軸ごとの補足 → 判断が変わる条件 → 未確認 → 出典
- 軸は相手の判断に効くものを3〜6個。全候補で値が同じ軸は外す
- 各候補に強み・弱み・違いを一言ずつ書く
- 各セルの値は同じ時点・同じ条件で確かめる。確かめられなかったセルは空欄にせず「未確認」と書く
- 落とし穴: 候補ごとに情報の新しさが違う。片方だけ公式、片方は記事、という比べ方になっている

## 事例集

他社・他者の取り組みを集める依頼。

- 構成: 結論（事例から読み取れる共通点と、当てはまらない条件）→ 事例の表（誰が / 何を / いつ / 結果の数字 / 出典番号）→ 相手の状況に移すときの注意 → 出典
- 結果の数字は、誰が測ったかを書く（当事者の発表か、第三者の調査か）
- 提供元が紹介している導入事例は、宣伝の性格があると明記する
- 落とし穴: 成功した事例だけを集める。うまくいかなかった例や撤退の例を1回は探す

## 真偽の確認

ある主張が正しいかを問われた依頼。

- 構成: 判定（正しい / 一部正しい / 誤り / 確かめられない）→ 根拠 → 正しい内容（誤りの場合）→ 出典
- 主張を分けて、1つずつ判定する。全体を1語で判定しない
- 確かめられないものを、もっともらしさで「正しい」にしない
