# 環境別・デフォルトから抜ける手順

**共通原則: フレームワークの既定トークンを直接使わず、自分のトークンを定義してから書く。**
既定値をそのまま使うことが、中央値に落ちる最大の経路。

---

## Tailwind CSS

### 最低限やること

1. **既定パレットを使わない。** `indigo` `violet` `purple` を含め、意味を持たせた独自の名前でトークンを定義する

```js
// tailwind.config.js（Tailwind v3系の書き方。v4 では CSS 側の @theme で同等の定義を行う）
theme: {
  colors: {
    ink:     { DEFAULT: '#1c1917', muted: '#57534e', faint: '#a8a29e' },
    surface: { DEFAULT: '#ffffff', sunken: '#faf9f7', raised: '#ffffff' },
    line:    '#e7e5e4',
    accent:  { DEFAULT: '#0f5132', hover: '#0a3d26', faint: '#e8f0ec' },
    danger:  '#9f1239',
  },
  // 既定の spacing / borderRadius も必要に応じて絞る
  borderRadius: { none: '0', sm: '2px', DEFAULT: '4px', lg: '8px' },
}
```

2. **クラス名の禁止リストを自分に課す**

```
from-* to-* via-*（グラデーション）/ backdrop-blur / rounded-2xl 以上 /
shadow-xl 以上 / hover:scale-* / animate-pulse（ローディング以外）
```

3. **任意値（`w-[347px]`）を多用しない。** スケールから外れた値が増えるとリズムが壊れる

### v4 を使う場合

色・間隔・書体は CSS の `@theme` で定義する。既定パレットは上書きするか、使わない方針をチーム内で明文化する。
バージョンごとに設定方法が変わるため、**公式ドキュメントで現行の記法を確認してから書く**（記憶で書かない）。

## shadcn/ui などのコンポーネントライブラリ

既定形のまま使うと、他のプロダクトと見分けがつかなくなる。**導入後、最低限この4つを上書きする。**

1. **色トークン**（`--primary` 等）を自分の基準色に差し替える
2. **角丸**（`--radius`）を小さくする。既定の 0.5rem は最も見慣れた値
3. **余白**（コンポーネント内の padding）を自分の基準に合わせる
4. **書体**を差し替える

そのうえで、**使うコンポーネントを絞る**。全種類を使うと「ライブラリのデモ」に見える。

---

## 素のCSS

1. **カスタムプロパティで先にトークンを定義する。** 値を直書きしない

```css
:root {
  --ink: #1c1917;
  --ink-muted: #57534e;
  --surface: #ffffff;
  --line: #e7e5e4;
  --accent: #0f5132;

  --space: 8px;          /* すべての余白はこの倍数 */
  --radius: 4px;
  --leading-body: 1.8;
}
```

2. `rem` / `ch` を使い、文字サイズに連動させる。本文の折り返しは `max-width: 42ch` 程度
3. **リセットCSSの既定に任せない。** 見出しの余白・行間は自分で決める

## 既存デザインシステムがある場合

**このスキルより、そのデザインシステムが優先される。**
やることは1つ — システムのトークンを使い、独自の値を足さないこと。
「AIっぽい」と言われる原因は、システムを無視して既定値を混ぜている箇所にあることが多い。

---

## デザインツール（Figma 等）からの実装

- コンポーネント名・変数名をコードのトークン名と一致させる
- **デザイン側にない値をコードで発明しない**。必要なら先にデザインを直す
- 書き出した値をそのまま貼らない（デザインツールの影の値はコードでは強すぎることが多い）

---

## 画像・アイコンが用意できないとき

これが**絵文字とグラデーション玉が発生する最大の原因**。次の順で代替する。

1. 実際のスクリーンショット・図表・数値を使う
2. 記号・番号・罫線で構造を示す
3. 文字だけで成立するレイアウトに変える（余白と階層で見せる）
4. それでも埋まらないなら、**その要素自体を削る**

「何かで埋める」判断が、中央値への最短経路になる。
