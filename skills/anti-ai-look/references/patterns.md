# 情報の関係から形を選ぶ（資料・Web・アプリ共通）

見た目を整える前に、そのページや画面で「何と何の関係を見せるか」を決める。関係が同じなら、資料でも Web でもアプリでも、同じ考え方で形を選べる。カード・アイコン・大きな数字を既定で並べると、関係が見えないまま量産型の見た目になる。

ここに書く形の選び方は経験則（非公式）。数値の基準（コントラスト比・押せる領域）だけは出典を付けた。

## 1. 作り始める前の設計表

ページ（資料）または画面（Web・アプリ）ごとに1行書く。埋められない欄があるなら、その画面はまだ作れない。

| 項目 | 資料（ページごと） | Web・アプリ（画面ごと） |
|---|---|---|
| 目的 | 読者に判断・行動してほしいこと | 利用者がこの画面で終えたいこと |
| 主役 | 主張の1文 | 最も目立たせる1要素（主要な操作、数字、一覧のどれか） |
| 中身と根拠 | 数字・事例と出典 | 表示するデータと、その出どころ・更新時期 |
| 情報の関係 | 下の表から1つ | 下の表から1つ |
| 主な形 | 主図 | 主な部品 |
| 状態 | （不要） | 空（0件）・読み込み中・エラー・権限なし・大量データ・長い文字列 |
| 制約 | 前提・試算の条件 | 画面幅、権限、既存のデザインシステムや部品 |

## 2. 関係ごとの形

| 情報の関係 | 資料 | Web | アプリ | 避ける形 |
|---|---|---|---|---|
| 対等な比較（A案とB案） | 評価軸×案の比較表。左右5:5 | 比較表。行見出しは評価軸、推奨の列に理由を添える | 縦に並べた比較、または切り替えで同じ順序の項目を見せる | 同じ大きさのカード3枚に特徴を箇条書き |
| 現状と改善後 | 共通の行見出しで左右に並べる | 前後を並べ、変わった箇所だけ強調 | 前後の切り替え表示 | 前と後で項目の順序や単位が違う |
| 数量の大小 | 横棒（ゼロ基点、直接ラベル、同じ縮尺） | 横棒、または右揃えの数値と単位の表 | 右揃えの数値リスト、必要なら横棒 | 大きな数字を3つ並べる、円や箱の大きさで比べる |
| 全体と内訳 | 積み上げ棒、内訳表 | 内訳表と合計行 | 合計から内訳へ開く一覧 | 合計と内訳が一致しない円グラフ |
| 時間の変化 | 折れ線（予測は線種で区別） | 折れ線と期間の切り替え | 最新値と小さな推移の線 | 月次と累計を同じ線で混ぜる |
| 手順・流れ | 左から右の業務フロー（担当ごとのレーン） | 1から番号を振った手順 | 現在地と残りが分かる進行表示 | 番号の無いアイコンの列 |
| 予定・期限 | 共通の時間軸、判断日と責任者 | 日付順のタイムライン | 日付順のリスト、近い順 | 期間の長さが見た目に反映されない並べ方 |
| 状態 | 表の列にラベルで | 文字のラベルと色を併用 | 同左 | 色の点だけで状態を伝える |
| 探す・選ぶ | 表 | 検索と絞り込みつきの表（件数が多いとき） | 検索とリスト。行全体を押せる | 情報の少ないカードを格子状に並べる |
| 承認・確定 | 決議事項の一覧（対象・金額・期限・責任者） | 確認画面（対象・金額・取り消せるか） | 確認ダイアログ。ボタンは操作名（「削除する」） | 「OK」「はい」だけのボタン |
| 階層・構成 | 層構造図、入出力図 | 見出しの階層とパンくず | 階層を1段ずつたどる画面 | 意味の無い矢印の循環図 |

同じ関係が続くなら、同じ形を使い続けてよい。形を変えるのは関係が変わったときだけにする。

## 3. 媒体をまたいで共通の基準

- 番号（ページ、手順、項目）は1から始め、ゼロ埋めしない。数量の0はそのまま書く
- 主役は1つ。最も伝えたい数字や操作にだけ強調色を使う
- 左端を揃え、関係の近いものを近づける。グループの中の間隔は、グループどうしの間隔より狭くする（`fixes.md` の2）
- 余白は基準値1つの倍数だけを使う（`decisions.md` の3）
- 色だけで意味を伝えない。ラベル・形・位置を併用する
- 数字には単位・期間・定義を隣に書く。表の数値は右揃え、項目名は左揃え
- 文字と背景のコントラスト比は4.5:1以上、大きな文字は3:1以上（`fixes.md` の4に出典）
- ボタン・入力欄の枠、フォーカスの表示など、操作に必要な見た目と隣の色との差は3:1以上（WCAG 1.4.11 Non-text Contrast、レベルAA）
- 押せる領域は 24×24 CSS px 以上（WCAG 2.5.8 Target Size (Minimum)、レベルAA。間隔による例外あり）。主要な操作は 44×44 CSS px 以上を目安にする（WCAG 2.5.5 Target Size (Enhanced)、レベルAAA）

## 4. Web・アプリで追加して確認すること

- 幅390pxと1280pxで、横スクロール・はみ出し・重なりが無い
- 設計表の「状態」に書いたすべての状態を表示して確かめた（0件、読み込み中、エラー、権限なし、長い文字列、大量データ）
- キーボードだけで操作でき、フォーカスの位置が見える
- 入力欄のラベルは、入力中も欄の外に見えている。エラーは該当する欄の近くに、文字で書く
- 取り消せない操作の前に、対象と結果を示す確認がある
- 確認の方法: 画面を開けるなら `ui-checker` などでスマホ幅とPC幅のスクリーンショットを撮り、`design-reviewer` などの確認役に渡す。ソースには `scripts/check_ui.py` を実行する
