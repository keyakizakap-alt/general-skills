# 兆候の一覧と代替案

「AIが作った」と判定される具体的な特徴。**単体では問題にならないものもあるが、3つ以上重なると確実にそう見える。**

> 背景（非公式・複数の技術記事で共通して指摘 / 参照日 2026-09-18）:
> Tailwind CSS の既定色が indigo-500 であり、訓練データ中の出現数が突出していること、
> LLM が制約のない依頼に対して統計的な中央値を返すことが、見た目の均質化の主因とされる。
> 一次情報ではないが、**制約を明示すれば解消する**という対策の方向性は再現性がある。

---

## 色

| 兆候 | 代わりに |
|---|---|
| 紫→青のグラデーション背景（`from-purple-500 to-indigo-600` 等） | 単色背景。奥行きが要るなら明度差のみで作る |
| グラデーション文字（`bg-clip-text text-transparent`） | 単色。強調は太さ・大きさ・余白で作る |
| indigo / violet / purple を基準色にする | 業種と印象から選び直す。迷ったら濃紺・深緑・レンガ・墨など彩度を落とした色 |
| 背景にぼかした色の玉（`blur-3xl rounded-full` の装飾） | 削除する。情報量ゼロで容量だけ食う |
| ダークモードが `slate-900` 一択 | 背景に僅かに色味を入れる（青寄り・茶寄り）。真っ黒も選択肢 |
| 色数が多い（5色以上のアクセント） | 基準色1 + 中立色2〜3段 + 警告色。それ以上増やさない |

## 文字

| 兆候 | 代わりに |
|---|---|
| Inter だけ / 既定サンセリフだけ | 見出しと本文で別書体。日本語は和文フォントを先に決め、欧文を合わせる |
| 見出しが全部 `font-bold` で同じ調子 | 階層を大きさと余白で作り、太さは1〜2段階に抑える |
| 行間が全部同じ | 見出しは詰め、本文は緩める（本文 1.7〜1.9、見出し 1.2〜1.4 が目安） |
| 中央揃えの長文 | 本文は左揃え。中央揃えは3行までの短文に限る |
| 日本語に欧文の字間調整をそのまま適用 | 和文は字間を触らないか、僅かに（約物の詰めは別途対応） |

## レイアウト

| 兆候 | 代わりに |
|---|---|
| 同じカード3枚横並び + 小アイコン + 2行テキスト | 数を変える / 1つを大きくする / 表・リスト・図に置き換える |
| 全セクションが中央揃えで上下に積まれている | 左揃えのセクションを混ぜる。基準線を1本通す |
| ベントーグリッド（大小のタイルを敷き詰める） | 情報に構造があるときだけ使う。装飾目的なら使わない |
| 全要素が等間隔 | 関係の近いものを寄せ、遠いものを離す。間隔差で構造を示す |
| ヒーローが「大見出し + 説明文 + ボタン2つ + スクショ」 | 主役（Step 1の5番）を1つに絞り、他を削る |
| 画面の隅々まで要素で埋まっている | 意図的に空ける。余白は失敗ではない |

## 装飾

| 兆候 | 代わりに |
|---|---|
| 角丸 + 枠線 + 影を全部使う | 3つのうち1つだけ選ぶ |
| `rounded-2xl` `shadow-lg` の組み合わせが全要素に | 角丸は小さく（4〜8px）するか、四角のままにする |
| すりガラス（`backdrop-blur` + 半透明白） | 使わない。重なりが必要なら実体のある面で区切る |
| `hover:scale-105` などの拡大ホバー | 色か枠線の変化に留める |
| グラデーション枠線、光る枠 | 削除 |
| アニメーションが常時動いている | 動きは操作への応答にだけ使う |

## アイコン・画像

| 兆候 | 代わりに |
|---|---|
| 絵文字をアイコン代わりに（🚀 ✨ 🎯 💡 🔒） | 記号・番号・図版。用意できないならアイコンなしで成立させる |
| アイコンセットの既定形をそのまま全面採用 | 使う数を減らす。1画面に5個以上は多い |
| 抽象的な3Dレンダリング画像、意味のないイラスト | 実際のスクリーンショット、図解、写真。なければ入れない |
| 人物写真がすべてストック風 | 実物を使うか、写真を使わない構成にする |

## コピー

| 兆候 | 代わりに |
|---|---|
| 「〜を、もっと自由に」「次世代の〜」「〜を再定義する」 | 主語・目的語・数字を入れる（誰が何をどれだけ） |
| "Transform your workflow" "Build the future" "Supercharge" | 同上。具体的な動詞と対象に置き換える |
| 「AI搭載」「Powered by AI」バッジ | 何ができるかを書く。技術名は機能の説明にならない |
| 特徴が全部3語の体言止め | 文にする。説明できない特徴は削る |
| ダミーテキストのまま整えられている | 実データ・実文言を入れてから整える（順序が逆だと必ず均質になる） |

## 実装の兆候

| 兆候 | 代わりに |
|---|---|
| フレームワークの既定トークンをそのまま使用 | 独自トークンを定義してから書く |
| コンポーネントライブラリの既定形をそのまま | 少なくとも色・角丸・余白・書体は上書きする |
| ブレークポイントが既定のまま、内容と無関係 | 内容が壊れる幅で切る |
| ダークモードが色の機械的な反転 | 明度関係を設計し直す（反転すると彩度が破綻する） |

---

## 重なりの判定

- **1〜2個**: 気にならない
- **3〜4個**: 「テンプレっぽい」と言われる
- **5個以上**: 「AIが作った」と即座に判定される

`scripts/check_ui.py` はこの重なりを数える。個別の兆候を潰すより、**重なりを減らすことを優先する**。
