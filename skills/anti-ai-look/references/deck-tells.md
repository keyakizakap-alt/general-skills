# 資料（スライド）の兆候と直し方

UI の兆候（`ui-tells.md`）と文章の兆候（`writing-tells.md`）は資料にもそのまま当てはまる。ここでは資料に特有のものを挙げる（経験則・非公式）。

| 兆候 | 直し方 |
|---|---|
| タイトルが名詞だけ（「概要」「課題」「まとめ」） | そのスライドで言いたいことを1文で書く（例: 「問い合わせの4割は請求書の再発行」） |
| 全スライドが「見出し + 箇条書き3つ + アイコン」 | 内容ごとに形を変える。比較は表、推移はグラフ、手順は番号付きの流れ、主張は大きな1文 |
| 「3つのポイント」「3つのメリット」の連発 | 実際の数で書く。並べる必要がなければ1つに絞る |
| 表紙が紫〜青のグラデーション + 抽象的な3D画像 | 単色の地 + タイトル + 日付・作成者。画像は内容と関係があるときだけ |
| 絵文字やアイコンで各項目を飾る | 外す。番号や太さの差で区別する |
| ストック写真の人物（握手、会議、PCを見て笑う人） | 実物の写真・スクリーンショット・図に替える。無ければ入れない |
| 装飾目的の図（意味の無い矢印の循環図、ピラミッド） | 図にしかできない情報（関係・順序・量）があるときだけ図にする |
| 数字に出典が無い / 「約〜%向上」など根拠が不明 | 出典と取得日を付ける。根拠が無ければ数字を出さない |
| 全文が中央揃え | 本文は左揃え。中央揃えはタイトルと短い1文だけ |
| 最後が「ご清聴ありがとうございました」だけ | 「次の一手」「お願いしたい判断」で終える |
| すべてのスライドで同じ文字量 | 重要なスライドほど文字を減らし、補足は話者メモや付録へ |
| どのスライドにも強調色が散らばっている | 強調色は1スライド1か所。最も伝えたい数字か語にだけ使う |

## 直す順番

1. 全スライドのタイトルだけを抜き出して読む。それで話の筋が通らなければ、構成から直す
2. 各スライドの形（箇条書き・表・図・1文）が内容に合っているかを見る
3. 文章の兆候を `scripts/check_text.py` で洗う（原稿の Markdown やテキストに対して）
4. 見た目の兆候は、HTML 資料なら `scripts/check_ui.py`、pptx なら画像にして目で確認する
