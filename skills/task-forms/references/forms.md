# 型の一覧（構成・制約・落とし穴）

長さの数字は目安で、依頼や媒体の指定があればそちらに従う。目安の根拠は公的な基準ではなく、このスキルの運用上の既定値。
各型とも「構成」は上から順に書く。該当しない要素は見出しごと省く。

## 即答

- 構成: 答え（1〜2文）→ 理由か根拠（1〜3点）→ 例外や注意（あれば1つ）
- 制約: 全体300字以内を基本にし、相手が詳細を求めたら伸ばす。見出しを付けない
- 落とし穴: 背景説明から始める。「場合によります」で終える（場合を2〜3個に分けて、それぞれの答えを書く）

## 比較・選定

- 構成: 推奨1つと決め手（1〜2文）→ 比較表 → 推奨が変わる条件 → 選ばなかった理由
- 制約: 表の軸は3〜5個、相手の判断に効く順に並べる。全候補が同じ値の軸は表から外す。各候補に強み・弱み・違いを一言ずつ。価格や仕様には確認日
- 落とし穴: 総合点で決める（重み付けは恣意的になる。決め手の軸を1つ言葉で示す）。全候補を等しく褒める

## 判断メモ

- 構成: 誰が、何を、いつまでに決めるか → 推奨案と費用・期間 → 根拠（3点以内）→ 見送った場合に起きること → リスクと打ち手 → 決めた後の最初の一手
- 制約: A4で1枚、600〜900字。金額・工数・期日は数字で書き、試算は前提と計算式を残す
- 落とし穴: 判断してほしい事項が最後に出てくる。選択肢を3つ並べて推奨を書かない。実績と試算を混ぜる

## 解説

- 構成: 一言の定義 → 身近な1例 → 仕組み（3段以内）→ よくある誤解を1つ → 理解を確かめる問いを1つ
- 制約: 新しい用語は一度に3つまで。相手がすでに知っているものに1つ結びつける。図にできる関係（流れ、階層、対比）は図か表にする
- 落とし穴: 歴史や分類から入る。正確さのために例外を先に全部書く（例外は最後に1つ）

## 手順書

- 構成: 完了時の状態と所要時間 → 用意するもの → 番号付きの手順 → うまくいかないとき
- 制約: 1手順に1動作。各手順に「こうなれば成功」を添える。コマンドや入力値はそのまま貼れる形で書く。取り消せない操作の直前には警告を置く
- 落とし穴: 手順の途中で初めて前提条件が出てくる。「適切に設定する」のように値を書かない

## 文面（メール・チャット）

- 構成: 用件と相手にしてほしいこと（1文目）→ 必要な情報（日時・場所・金額・添付）→ 期限と返信の方法
- 制約: チャットは200字以内、メールは400字以内を基本にする。依頼は1通に1つ。日時は曜日つきで書く。件名は用件と期限を含める
- 落とし穴: 挨拶と経緯が長く、用件が3段落目に出る。相手が選べない質問をする（候補日を2〜3個出す）
- 補足: 敬語の程度は相手との関係で決める。分からなければ丁寧寄りと簡潔寄りの2案を出す

## 報告

- 構成: 現在の状態（順調 / 遅延 / 停止 / 完了）と相手への影響 → 起きたこと → 対応したこと → 次の予定と、相手に頼みたいこと
- 制約: 状態は1語で言い切る。時刻・件数・割合は数字で書く。原因が確定していなければ「調査中」と書き、推測は推測と書く
- 落とし穴: 時系列で長く書き、結論が最後になる。悪い知らせを和らげて状態が読み取れなくなる

## 企画の骨子

- 構成: 誰の何がどう変わるか（1文）→ 今の困りごとと証拠 → 案の中身 → 代わりの手段との違い → 最小の試し方と、やめる基準 → 必要な費用・期間・人
- 制約: 1枚、800字前後。困りごとには観察した事実か数字を1つ以上。最小の試し方は2週間以内に始められる大きさにする
- 落とし穴: 機能の一覧になる。「需要がある」を根拠なしで書く。やめる基準が無い

## 議事録・要約

- 構成: 決まったこと → 宿題（担当・期日つき）→ 決まらなかったことと次の場 → 経緯（必要な分だけ）
- 制約: 元の長さの1割以下を目安にする。固有名詞・数字・日付は元の表記のまま残す。発言の解釈を足すときは「解釈」と書く
- 落とし穴: 発言順に並べる。元に無い結論を補う。担当や期日が曖昧な宿題をそのまま書く（曖昧だったと明記する）

## 計画

- 構成: 期日と完成の定義 → 最初の一手（今日できること）→ 区切りごとの成果物と日付 → 最大のリスクと予備日 → 削れるもの
- 制約: 区切りは3〜6個。各区切りは「何ができていれば通過か」で書く。全体の2割を予備に取る
- 落とし穴: 作業の一覧で終わり、日付が無い。全部が予定どおり進む前提になっている

## 発信文（SNS・記事・告知）

- 構成: 読み手にとっての得か、具体的な出来事（1行目）→ 中身 → 読み手が次にすること
- 制約: 1投稿1主張。媒体の文字数と仕様は公式で確かめる。数字や体験には、いつ・どこで・誰がを入れる。ハッシュタグと絵文字は媒体の慣習の範囲で最小限にする
- 落とし穴: 「〜について書きました」で始める。誰にでも当てはまる教訓で締める。効果を誇張する（景品表示や各媒体の規約に触れる恐れがある場合は要確認と書く）

## 応募文・ピッチ

- 構成: 審査基準ごとの答え（基準の順に）→ 作ったものと動く証拠 → 自分たちだから出来た理由 → 今後の一手
- 制約: 募集要項の字数・形式・提出物を最初に書き出し、最後に照合する。主張ごとに証拠（デモ、数字、利用者の声、コード）を1つ付ける。審査員が1分で読める要約を冒頭に置く
- 落とし穴: 技術の説明が長く、誰の何を解決したかが無い。審査基準に無い長所を強調する。要項の条件を満たさない

## 原因調査

- 構成: 最も疑わしい原因と確かめ方 → 分かっている事実（再現条件、エラー文、変更点）→ 仮説の一覧（確からしい順、各1行で確かめ方つき）→ 直し方と副作用
- 制約: 事実と仮説を分ける。確かめ方は1つ5分以内でできるものから並べる。エラー文は原文のまま引用する
- 落とし穴: 確かめる前に直し方を複数同時に勧める。再現条件を聞かずに一般論を並べる

## アイデア出し

- 構成: 推す1案と理由 → 軸の違う案（3〜7個、各案に一言の特徴と最初の試し方）→ 意図して外した方向
- 制約: 似た案を並べない。案どうしの違いを軸（対象、価格、手段、時期など）で示す。少なくとも1案は依頼の前提を外したものにする
- 落とし穴: 10個以上を等しい重みで並べる。どれも実行の一手が無い

## 学習支援

- 構成: 今日やる量（時間と範囲）→ 要点の解説 → 理解を確かめる問い（答えと解説つき）→ 間違えたときの戻り先 → 次回の予定
- 制約: 1回の量は相手の使える時間に合わせる。問いは「覚えたか」だけでなく「使えるか」を1問入れる。試験範囲・配点・日程は公式で確かめる
- 落とし穴: 計画だけ立派で初日の量が多すぎる。解説を読ませるだけで問いが無い

## データの読み取り

- 構成: 言えること（1文）→ 根拠の数字と比較対象 → 言えないことと理由 → 次に見るべき数字
- 制約: 割合には分母を書く。期間・単位・集計の定義を明記する。相関と因果を分ける。グラフは1枚に1主張
- 落とし穴: 数字を並べるだけで主張が無い。標本が小さいのに言い切る。都合のよい期間だけ切り取る
