# task-forms

**目的**: どんな依頼でも、受け取った人が手直しせずに使える形で返す。
読み手が驚くのは飾りや分量ではなく、「次に聞こうとしていたこと」「そのまま貼れる形」「自分では気づかなかった前提の誤り」が先に出てきたとき。このスキルはそれを手順にする。

## 0. 専用スキルがあればそちらへ

| 依頼 | 任せる先（使える環境なら） |
|---|---|
| プロンプト・エージェントの指示 | `prompt-architect` |
| スライド・提案資料 | `deck-sprint` |
| アプリ・LP の実装 | `ryo-product-delivery` |
| 出典つきの調査 | `research-brief` |
| 完成物の検品 | `deliverable-check` |

当てはまらない依頼、および専用スキルの中で書く文章には、下の手順を使う。プロジェクトの規約があればそちらを優先する。

## 1. 3つを読む（質問で止めない）

- 目的: この成果物を受け取った後、相手は何をするか（決める / 送る / 実行する / 覚える / 誰かに説明する）
- 読み手: 誰が読むか。その話題をどこまで知っているか。読むのに何分使えるか
- 使い道: そのまま貼る / 転送する / 画面で見ながら作業する / 会議で読み上げる

書かれていない項目は最も実務的な値を推定する。推定のうち、外れると成果物が変わるものだけを、成果物の後ろに「前提」として示す（3行まで）。解釈しだいで成果物が別物になるときだけ、先にA案で仕上げてから1問添える。

## 2. 型を1つ選ぶ

各型の構成・数値の制約・落とし穴は `references/forms.md`。複数にまたがる依頼は、相手の「次の行動」に合う型を主にし、他は節として入れる。

| 型 | 使う場面 | 冒頭に置くもの |
|---|---|---|
| 即答 | 質問に答える | 答えそのもの |
| 比較・選定 | どれを選ぶか | 推奨1つと決め手 |
| 判断メモ | 承認・決裁を求める | 誰が何をいつまでに決めるか |
| 解説 | 仕組みや概念を理解したい | 一言の定義と、身近な1例 |
| 手順書 | 作業をやり遂げたい | 完了時の状態と所要時間 |
| 文面 | メール・チャットを送る | 用件と相手にしてほしいこと |
| 報告 | 進捗・結果・障害を伝える | 現在の状態と相手への影響 |
| 企画の骨子 | 新しい案を通したい | 誰の何がどう変わるか |
| 議事録・要約 | 長い内容を短く渡す | 決まったことと宿題 |
| 計画 | 期日までに終わらせたい | 期日・最初の一手・最大のリスク |
| 発信文 | SNS・記事・告知 | 読み手にとっての得 |
| 応募文・ピッチ | 審査・選考を通りたい | 審査基準に対する答え |
| 原因調査 | うまく動かない | 最も疑わしい原因と確かめ方 |
| アイデア出し | 選択肢を広げたい | 推す1案と、軸の違う案 |
| 学習支援 | 試験・習得 | 今日やる量と、理解を確かめる問い |
| データの読み取り | 数字から何が言えるか | 言えること1つと、言えないこと |

## 3. 全型に共通の制約

1. 1文目が答え。前置き、依頼の言い直し、「以下にまとめます」を書かない
2. 立場を取る。選択肢を並べて終わらせず、推奨1つと「判断が変わる条件」を書く
3. 各節に具体物を1つ以上入れる（数字、固有名詞、例、コマンド、文面）。入れられない節は削る
4. 長さの上限を書く前に決める（型ごとの目安は `references/forms.md`）。上限を超えたら内容を足す前に削る
5. 形は内容に従う。並列は箇条書き、複数の軸の比較は表、因果と理由は文章、順序は番号。見出しは3節以上あるときだけ
6. 変わりうる事実（仕様、価格、提供状況、制度、役職）は確かめてから書き、出典と確認日を付ける。確かめられなければ「未確認」と書く。推測には「推測」と書く
7. 相手の言葉を使う。相手が使っていない専門語や社内用語は、初出で一言説明するか言い換える
8. 依頼文に書いてある事実を、節を立てて言い直さない。相手がまだ知らないことから書く
9. 相手の名義で出す成果物（文面、報告、応募文）に、依頼に無い約束・期日・数字・事実を足さない。入れたほうが良いものは、成果物の外で1行の提案にする

## 4. 一歩先を1つだけ足す

`references/one-step-ahead.md` の7種類から、この相手に最も効くものを1つ（多くて2つ）選ぶ。全部は入れない。

- 次の質問への先回り / そのまま使える形 / 前提の誤りやリスクの指摘 / 判断が変わる条件 / 最も強い反対意見 / 捨てた選択肢と理由 / 実際に確かめた結果

依頼されていない作業（別の成果物、追加の機能）を勝手に増やさない。足すのは相手の次の一手を短くするものだけで、長さの上限に収める。
案を複数並べるのは、どちらが合うかを相手にしか決められないときだけ。それ以外は1案に絞り、変えるならどこかを1行で添える。

## 5. 出す前に確かめる

コマンドを実行できる環境では機械検査をする。

```bash
python3 scripts/check_form.py <ファイル>                 # 前置き・締めの定型、穴埋めの残り、出典の書式、構造の偏り
python3 scripts/check_form.py <ファイル> --max-chars 800  # 長さの上限も検査
```

実行できない環境では、同じ項目を目で確かめる。そのうえで次の3つを読み直す。

- 冒頭だけ読んで、相手は行動できるか
- 宛先や題材を別のものに置き換えても通じる文が無いか（あれば具体物を足すか削る）
- 削っても意味が変わらない文が無いか
- 依頼が求める範囲（試験範囲、対象期間、候補の全部）を、絞り込みの途中で落としていないか
- 冒頭の結論と、後ろの数字や計算が食い違っていないか（計算は検算する）
- 字数や枚数の枠が指定されているとき、枠の8割以上を使っているか（余らせた分は根拠や具体例に使う）

## 成果物の後ろに付けるもの（必要なときだけ）

```
前提: <推定して置いた値。相手が直せるように>
未確認: <確かめられなかった事実と、確かめ方>
出典: <タイトル／URL／公式・非公式／取得日 YYYY-MM-DD>
```

付けるのは、相手の判断か次の行動を変えるものだけ。合わせて5行までにする。次のものは書かない。

- 依頼文の言い直し、誰でも分かる前提（今日の日付、依頼文から明らかな条件）
- 本文ですでに書いた注意の繰り返し
- 確かめようのない一般的な断り書き（「状況により異なります」など）

文面やコードのように、そのまま貼って使う成果物の中には、これらを混ぜない（成果物と分けて書く）。
