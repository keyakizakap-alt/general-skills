# 品質証拠レポート（雛形）

複雑な変更・公開前の確認で使う。軽微な修正は、最終回答に同じ区別の短いチェックリストを書けば足りる。
完了報告の区別（実装済み / ローカル検証済み / 本番検証済み / 未検証）は、`references/report-contract.md` の4区分に従う。

| 項目 | 結果 | 証拠 | 環境 |
| --- | --- | --- | --- |
| 完了条件と主要な操作フローを定めた | NOT_RUN | | |
| 型検査 / Lint | NOT_RUN | 実行したコマンドと終了コード | |
| 単体・結合テスト | NOT_RUN | 実行したコマンドと終了コード | |
| E2E: 主要フロー | NOT_RUN | 操作 → 期待 → 観測 | |
| E2E: エラー・境界ケース | NOT_RUN | 操作 → 期待 → 観測 | |
| 回帰: 影響を受けうる隣接フロー | NOT_RUN | 操作 → 期待 → 観測 | |
| モバイル表示 | NOT_RUN | 画面幅と確認した項目 | |
| セキュリティ確認（公開前のみ） | NOT_RUN | 秘密情報の検索、認可、依存パッケージ | |
| 公開URLでの確認（公開前後のみ） | NOT_RUN | URL、確認した時刻、操作 | |

結果の値は `PASS` / `FAIL` / `NOT_RUN`（未実行）/ `BLOCKED`（実行できない）/ `NOT_APPLICABLE`（対象外）のいずれか。`BLOCKED` と `NOT_APPLICABLE` には理由を書く。

- 必須の項目が `PASS` でないときは「検証済み」と書かない。
- `BLOCKED` には、足りない権限・認証情報・ツールを具体的に書く。
- ビルドの成功だけでは E2E の `PASS` にならない。
