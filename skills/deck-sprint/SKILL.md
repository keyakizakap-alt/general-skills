# deck-sprint

**目的**: 下書きで終わらせず、読者がそのまま判断に使える資料を1回の依頼で仕上げる。数字と事実は確かめ、確かめられないものは隠さず「未確認」と書く。

## 0. 環境に合わせて進め方を選ぶ

| 環境 | 進め方 |
|---|---|
| Claude Code でワークフローが使える（`deck-build` が `/` メニューにある、またはプラグイン `general-skills` 導入済み） | `deck-build` ワークフローに args（下表）を渡して実行し、結果を確認して報告する。Pro プランは `depth: "lite"`（既定） |
| それ以外（claude.ai のチャット、ワークフロー無効） | 下の手順 1〜6 を順に行う |

`deck-build` の args: `{topic, audience?, goal?, format?: "pptx" | "slides" | "html", sources?: [パスやURL], slides?: 枚数, outDir?, depth?: "lite" | "full"}`

## 1. 前提を決める（質問は最小限）

テーマ・読者・ゴール（読後に何を判断/行動してほしいか）・枚数・形式・参照資料を確定する。書かれていなければ既定値を置き、資料の冒頭か報告で「前提」として示す。成果を大きく変える不明点だけ1問聞く。

## 2. 構成案を比べる

「結論先行」と「読者の疑問の順」など、2つ以上の切り口で構成を考え、読者が判断しやすい方を土台に1つに決める。全体の主張（key message）を1文で書けない構成は採らない。

## 3. 執筆

`references/quality.md` の基準で書く。要点: 1スライド1メッセージ、タイトルはメッセージ文、本文は1枚5項目まで、図表案、話者メモ、数字・事実には出典。

## 4. 事実確認（作成者とは別の視点で）

主張ごとに一次情報で確かめ、verified / unverified / refuted に分ける。refuted は直すか削除、unverified は「未確認」と明記する。確認役のサブエージェント（`fact-checker` 等）が使えれば任せる。

## 5. 組版

形式ごとの作り方は `references/formats.md`。

- **pptx**: pptx スキルがあればその手順に従う
- **claude.ai の Slides / Docs**: その環境の Slides / Docs の作成機能を使う。公開や共有は利用者の確認後
- **HTML**: 1ファイル、外部スクリプトなし、レスポンシブ、ダークモード対応

既存ファイルは上書きしない。

## 6. 体裁検査と報告

`references/quality.md` の検査項目で確認する（実行できない検査は「未実行」）。AIっぽさ（常套句、名詞だけのタイトル、量産型の見た目）もここで点検する。報告は結論から:

```
## 完成: <タイトル>（<形式>、<枚数>枚）
- ファイル / リンク:
- 主張: <key message>
- 事実確認: 確認 N 件 / 未確認 N 件（スライド番号） / 修正 N 件
- 体裁検査: 確認したこと / 未実行とその理由
- 前提にしたこと:
- 次の一手:
```
