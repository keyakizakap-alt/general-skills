# deck-sprint

**目的**: 下書きで終わらせず、読者がそのまま判断に使える資料を1回の依頼で仕上げる。数字と事実は確かめ、確かめられないものは隠さず「未確認」と書く。

## 1. 環境に合わせて進め方を選ぶ

| 環境 | 進め方 |
|---|---|
| Claude Code でワークフローが使える（`deck-build` が `/` メニューにある、またはプラグイン `general-skills` 導入済み） | `deck-build` ワークフローに args（下表）を渡して実行し、結果を手順 6〜7 で確認して報告する。Pro プランは `depth: "lite"`（既定） |
| それ以外（claude.ai のチャット、ワークフロー無効） | 下の手順 2〜7 を順に行う |

`deck-build` の args: `{topic, audience?, goal?, format?: "pptx" | "slides" | "html", sources?: [パスやURL], slides?: 枚数, outDir?, depth?: "lite" | "full"}`

プロジェクトに資料の規約（`AGENTS.md`、資料作成スキル、テンプレート）があれば、そちらを優先する。

## 2. 前提を決める（質問は最小限）

テーマ・読者・ゴール（読後に何を判断/行動してほしいか）・枚数・形式・参照資料を確定する。判断を求める資料なら、冒頭で「誰が、何を、いくらで、いつまでに判断するか」を示す。書かれていなければ既定値を置き、資料の冒頭か報告で「前提」として示す。成果を大きく変える不明点だけ1問聞く。

## 3. 構成案を比べ、ページ設計表を作る

「結論先行」と「読者の疑問の順」など、2つ以上の切り口で構成を考え、読者が判断しやすい方を土台に1つに決める。全体の主張を1文で書けない構成は採らない。

組版の前に、全ページの設計表を作る: ページ番号 / 主張（1文） / 根拠 / 情報の関係 / 主図 / 前提・制約。主図は情報の関係から選ぶ（比較は比較表、大小は横棒、内訳は内訳表、手順は業務フロー、時期は時間軸、承認は決議一覧）。選び方と余白・文字組みの基準は `references/layout-patterns.md`。同じカード配置を毎ページ繰り返さない。

## 4. 執筆

`references/quality.md` の基準で書く。要点: 1スライド1メッセージ、タイトルは主張の文、本文は1枚5項目まで、話者メモ、数字・事実には出典。試算・目標・実測を分け、計算式と前提を残す。

## 5. 事実確認（作成者とは別の視点で）

主張ごとに一次情報で確かめ、verified / unverified / refuted に分ける。refuted は直すか削除、unverified は「未確認」と明記する。確認役のサブエージェント（`fact-checker` 等）が使えれば任せる。

## 6. 組版と体裁検査

形式ごとの作り方は `references/formats.md`。

- **pptx**: pptx スキルがあればその手順に従う。無く、python-pptx がある環境では `scripts/slide_kit.py`（編集できる図形・表、1始まりのページ表記、ノート）で組める
- **claude.ai の Slides / Docs**: その環境の作成機能を使う。公開や共有は利用者の確認後
- **HTML**: 1ファイル、外部スクリプトなし、レスポンシブ、ダークモード対応

既存ファイルは上書きしない。組んだら次を確認する（実行できない検査は「未実行」）:

- pptx: `python3 scripts/check_deck.py <ファイル>.pptx --slides <枚数>` で枚数・ノート・ページ表記・ゼロ埋め・PDFのページ数を検査する
- PDF にできる環境（LibreOffice）では、ページ画像の縮小一覧で配置の反復を、1枚ずつはみ出し・重なり・日本語の崩れを見る。確認役（`design-reviewer` 等）があれば画像を渡して見てもらう
- `references/quality.md` の検査項目、`references/layout-patterns.md` の納品前の確認

## 7. 納品と報告

- ファイル名は英数字。編集用（pptx）と配布用（PDF）を分けて保存する
- 保存先が Git リポジトリなら、コミット・push は利用者の承認を得て行い、リモートに反映されたことを確かめてからファイルのリンクを渡す。共有ドライブ等に置く場合は、共有範囲を利用者に確認する
- 実行環境内のパスや、受け渡しを確認していないリンクを、ダウンロード先として案内しない

報告は結論から:

```
## 完成: <タイトル>（<形式>、<枚数>枚）
- ファイル / リンク:
- 主張: <key message>
- 事実確認: 確認 N 件 / 未確認 N 件（スライド番号） / 修正 N 件
- 体裁検査: 確認したこと / 未実行とその理由
- 前提にしたこと（試算の前提を含む）:
- 次の一手:
```
