# 資料の品質基準と検査項目

## 構成

- 冒頭3枚で「結論・理由・求める判断」が分かる
- 各スライドのタイトルは、そのスライドで言いたいこと（メッセージ文）。「現状」「課題」のような名詞だけのタイトルにしない
- 1スライド1メッセージ。本文は箇条5項目まで、1項目は2行以内
- 根拠（数字・事例）はメッセージの直後に置く
- 最後は「次の一手 / 求める判断」で終える

## 番号

- ページ・章・項目の番号は1から始め、ゼロ埋めしない（`1 / 9`、`1`、`2`）。`01`、`0 / 9`、0番の導入ページを作らない
- 数量としての0（0件、0時間）や計算上の0はそのまま書く

## 内容

- 数字・仕様・機能ステータスには出典URLと取得日。公式か非公式かを区別する
- 確認できない内容は作らず「未確認」と書く
- 誇張・比喩・宣伝文句（「革命的」「圧倒的」など）を使わない
- 日時・通貨・単位・税込/税別は依頼や元資料の指定に合わせる。指定のない換算や税計算をしない
- 前提にしたこと（読者、期間、範囲）を明記する
- 見出しは実務上の主張にする。「価値を最大化」「未来を切り拓く」のような標語に置き換えない。動作と対象を書く（例: 「業務を高度化」ではなく「注文書の品番・数量・納期を抽出し、担当者が原本と照合する」）

## 判断を求める資料（提案書・経営会議資料）

- 試算・目標・実測を区別する。架空の導入実績や根拠のない精密値を作らない。単価・件数・導入の進み方・計算式を残す
- 現金支出の削減と、創出時間の金額換算を分ける。ROI と回収期間は定義と前提を併記し、時間の創出を現金の回収と呼ばない
- 判断を左右する制約は本文に置く。小さな脚注だけに追いやらない。長い説明は本文を縮小せず、話者メモや別紙に移す
- 別の資料と前提が違う場合は混ぜない。承認された前提を引き継ぎ、別資料は無断で書き換えない
- 話者メモは、担当者が説明する自然な話し言葉で書く。定型の導入・締めや売り文句を繰り返さない

## 見た目

- 配色は3色まで（地の色・文字の色・強調色1つ）。強調色は1スライド1か所
- 本文の文字は pptx で24pt以上、HTML で16px以上
- 余白を揃え、要素の左端を揃える
- 図表は「何を比べるか」が1つに絞れているものだけ使う。凡例と単位を付ける
- 紫〜青のグラデーション、絵文字アイコン、角丸カード3枚並びのような量産型の見た目を避ける
- タイトルを名詞だけにしない、何でも「3つのポイント」にしない、全スライドを同じ形にしない
- `anti-ai-look` スキルが使えれば、その資料用の兆候一覧と検査（文章: `check_text.py`、HTML: `check_ui.py`）で仕上げを確認する

## 検査項目（体裁検査で確認する）

| 項目 | 確認方法 |
|---|---|
| はみ出し・重なり | HTML: Playwright で幅390px/1280pxのスクリーンショット。pptx: 画像化（LibreOffice があれば）か、文字量と枠サイズの確認 |
| 横スクロール（HTML） | `document.documentElement.scrollWidth > innerWidth` |
| 文字量 | 1枚の箇条5項目以内、1項目2行以内 |
| 出典 | 数字・事実のあるスライドに出典がある |
| 未確認の明記 | unverified の主張に「未確認」と書いてある |
| 誤字・表記揺れ | 用語、全角/半角、数字の書式 |
| 番号 | 1始まり・ゼロ埋めなし。pptx は `scripts/check_deck.py` で検査できる |
| 発表者ノート | 全スライドにある（pptx は `check_deck.py`） |
| 配置の反復 | ページ画像の縮小一覧で、同じカード配置が続いていない |

実行できなかった検査は、理由とともに「未実行」と報告する。
