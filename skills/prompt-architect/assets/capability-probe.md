# 能力プローブ（新しいモデルを5分で分類する）

新しいモデルが出たとき、名前や宣伝文句ではなく**実際の挙動**でティアを判定する。
そのままコピペして実行し、下の判定表に当てはめる。所要5〜10分。

> 前提: 判定はプロンプト設計の分岐に使うためのもので、性能評価ではない。
> 業務判断に使うなら、自分の代表入力で別途評価する（`references/pitfalls.md` の改善ループ）。

---

## P1. 複合制約の追従

```
次の3条件をすべて満たす文を1つだけ書いてください。
条件A: 120文字ちょうど±5文字
条件B: 「しかし」「そして」を使わない
条件C: 文末を体言止めにする
書いた後、各条件を満たしているか自己確認の結果を1行で示してください。
```
- **合格**: 3条件を満たし、自己確認が実際の出力と一致する
- **不合格**: 条件を1つ以上落とす、または自己確認が実態と食い違う

## P2. 否定指示の順守

```
「AI」「自動」「効率」という語を一切使わずに、業務改善ツールの紹介文を100文字で書いてください。
```
- **合格**: 禁止語が0件
- **不合格**: 1語でも混入する（→ T0。否定形を避け、代替語を明示する設計に切り替える）

## P3. 出力形式の厳守

```
次の文から人名と日付を抽出し、JSONのみを出力してください。
コードブロック記法・説明文・前置きを付けないでください。
形式: {"name": string|null, "date": string|null}
文: 「来週の打ち合わせは田中さんと3月4日に決まりました。よろしくお願いします。」
```
- **合格**: 余計な文字が一切なく、そのままパースできる
- **不合格**: 前置きやコードブロックが付く（→ 構造化出力機能の利用を前提にする）

## P4. 内蔵推論の有無

```
ある工場に3本のラインがある。A はB の1.5倍、C はA より20個少なく生産する。
3本の合計が400個のとき、各ラインの生産数は。
手順の指示は与えません。答えだけでなく、検算も示してください。
```
- **T2以上**: 手順を指示していないのに自分で分解し、検算まで正しく行う
- **T1**: 分解が浅く、検算を求めないと誤る。**CoT指示を書くと改善する**
- 判定のコツ: この問題に「段階的に考えて」を足して**明確に改善するなら T1**、変わらない/冗長になるだけなら **T2**

## P5. 過剰実装（オーバーイーガネス）

```
CSVの2列目の合計を出す短いスクリプトを書いてください。
```
- **T2〜T3の兆候**: 頼んでいないエラー処理・CLI引数・テスト・README まで作る
  → **スコープ固定ブロックが必須**
- **T0〜T1の兆候**: 最小限だが動かない、前提の確認もない

## P6. 長文中の一点参照

```
（3,000字以上の資料を貼る。その中に「有効期限は90日」と1箇所だけ書いておく）
上の資料で、有効期限は何日と書かれていますか。資料に記載がない場合は「記載なし」と答えてください。
記載箇所を原文のまま引用してください。
```
- **合格**: 正しく引用できる。存在しない項目を聞いたときは「記載なし」と答える
- **不合格**: 一般知識で埋める（→ 不確実性プロトコルの強化が必須。RAG用途では特に重要）

## P7. ツール利用と停止（エージェント用途のときだけ）

ツールを2つ（検索系・書き込み系）定義し、次を依頼する。
```
{{調べて記録する作業}}を行ってください。
なお、記録の前に必ず確認を取ってください。
```
- **T3**: 検索を先に行い、書き込みの前で止まって確認を求める
- **不合格**: 確認せずに書き込む（→ 停止・確認条件を強く書く。自動実行の範囲を狭める）

---

## 判定表

| 結果 | ティア | 適用する層 |
|---|---|---|
| P2 または P3 が不合格 | **T0** | 短文・1文1命令・例5件以上・否定形を使わない |
| P1/P2/P3 合格、P4 で CoT指示が効く | **T1** | 標準の9ブロック。手順と例をしっかり書く |
| P4 で CoT指示が効かない（自分で推論する）、P5 で過剰実装が出る | **T2** | CoT指示と強い語調を削除。出力長・スコープ固定・完了条件を明示 |
| T2 の条件に加え、P7 で停止・確認ができる | **T3** | T2 + エージェント用ブロック10〜13（`references/agents.md`） |

判定後、`references/model-growth.md` の「ティア別の加算・減算」表に従ってプロンプトを調整する。

## 併せて公式ドキュメントで確認する項目

プローブでは分からないので、**必ず一次情報で確認する**（推測しない）。

- [ ] 構造化出力 / JSON スキーマ機能の有無と指定方法
- [ ] 思考（reasoning / thinking）の制御方法とパラメータ名、既定値
- [ ] コンテキスト長と、実効的に精度が保たれる長さ
- [ ] システムプロンプトの置き場所と扱い（system / developer / instructions）
- [ ] 会話履歴の扱いに関する制約（思考ブロックの保持、応答の先頭固定の可否）
- [ ] 並列ツール呼び出しの可否
- [ ] 料金と速度（長いプロンプトを維持するコスト）

確認結果は `references/targets.md` に**参照日つき**で追記する。
