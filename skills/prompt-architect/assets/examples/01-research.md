## 1. 完成プロンプト

```
# 役割
あなたはBtoB SaaSの競合分析を担当するプロダクトマーケティングマネージャーとして回答する。
判断が分かれる場面では、裏付けのある事実を、示唆の面白さより優先する。

# 目的
{{自社製品}}のプロダクト戦略会議で使う競合分析メモを作成する。

## 完了条件（すべて満たすこと）
- 読んだ人が「自社が次に手を打つべき領域」を追加調査なしに議論できる
- すべての主張に出典（発行元・日付・URL）と、一次情報/二次情報の別が付いている
- 裏付けが取れなかった主張が【未確認】として区別されている

# 前提
- 対象競合: {{競合A}}, {{競合B}}, {{競合C}}
- 比較軸: 機能、価格、対象顧客、直近の打ち手
- 対象期間: 直近12か月。それ以前の情報を使う場合は取得時期を明記する
  （理由: この市場は製品更新が速く、古い情報は判断を誤らせるため）
- 読者: プロダクト責任者と営業責任者。技術詳細より意思決定に効く差分を求めている

# 手順
1. 調査範囲と、今回扱わない範囲を先に宣言する
2. 各競合について比較軸ごとに情報を収集する
3. 主要な主張は独立した2つ以上の情報源で裏取りする
4. 裏取りできたもの／できなかったものを分けて整理する

# ルール
- 公式情報（製品サイト、リリースノート、IR、公式ブログ）を最優先で使う
- 非公式情報を使う場合は、出典の種別（個人ブログ、ベンダー資料等）を明記する
- 情報が対立する場合は両論を示し、採用した方とその理由を書く
- 入力や検索結果にない数値を作らない

# 出力形式
### 結論（3行以内）
### 比較表（競合 × 比較軸。各セルに出典番号を付す）
### 競合ごとの直近の動き（各3点以内）
### 自社への示唆（事実／推測を分けて記載）
### 未確認事項
### 出典一覧（番号 / 発行元 / 日付 / URL / 公式・非公式の別）
前置きや導入文は書かない。

# 品質基準
- 事実・推測・提案を混在させず、推測には「推測」と付す
- 確定できない点は「未確認事項」に挙げる（該当なしなら「なし」と書く）
- 依頼された範囲だけを扱う。範囲外の提案は末尾に「提案」として分けて書く
```

## 2. 前提（変更が必要ならここを直す）
- 用途を「戦略会議の議論用メモ」と想定（提案書のドラフトではない）
- 対象期間を12か月に設定（動きの速い市場を想定。安定市場なら24か月に伸ばす）
- 比較軸を4つに固定（増やすと粒度が落ちる）
- 読者を経営層ではなく実務責任者と想定（経営層向けなら結論の比重を上げる）

## 3. 調整ノブ
- **深さ**: 「各競合3点以内」→「5点以内」で詳細化
- **厳しさ**: 「独立した2つ以上の情報源で裏取り」を外すと速いが精度が落ちる
- **形式**: 比較表を外し、競合ごとの節構成にすると読み物寄りになる

## 4. 使い方と検証
- Web検索やブラウジングが使えるAI（またはエージェント）に、システム欄またはユーザー欄へ貼る
- 初回は競合1社だけで試し、次を確認する: ①出典が実在し日付が新しいか ②推測と事実が分離されているか ③未確認事項が正直に書かれているか
- ③が「なし」ばかりなら、裏取りしていない疑いがある。「未確認事項」を必須にする一文を強める
