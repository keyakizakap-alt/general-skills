# AIエージェント用プロンプト設計

対象: ツールを持ち、複数ターン自律的に動く構成（Claude Code / OpenAI Agents / LangGraph / 社内エージェント基盤 / MCP 連携など）。
チャット用プロンプトとの決定的な違いは、**失敗が積み上がる**ことと、**副作用が現実に起きる**こと。
9ブロックに加えて次の4つを必ず定義する。

---

## ブロック10: ツール使用方針

「どのツールがあるか」はツール定義側に書く。プロンプトに書くのは**選び方と使い分け**。

```
## ツールの使い方
- 事実を答える前に、必ず該当する情報源をツールで確認する。未確認の内容を断定しない
- 独立した複数の調査は並列に実行する。前の結果に依存する呼び出しは順に実行する
- 同じツールを同じ引数で2回以上呼ばない。結果が変わらない場合は方針を変える
- 引数が確定できない場合は推測値を入れず、確認するか {{代替手段}} を使う
- {{ツールA}}は{{条件}}のときだけ使う（{{理由}}）
```

チューニングの勘所:
- **使わなすぎ**: 「〜する前に必ず〜で確認する」と前置条件で縛る
- **使いすぎ**: 「すでに得た情報で答えられる場合は追加の呼び出しをしない」
- **同じ失敗のループ**: 「同一のエラーが2回続いたら、手法を変えるか停止して報告する」

---

## ブロック11: 停止条件と人間確認（最重要）

エージェント事故の大半はここの未定義が原因。**3種類**を必ず書き分ける。

```
## 完了とみなす条件
- {{検証可能な状態}}に達し、{{検証方法}}で確認できたとき
- 完了時は、実施内容・変更点・残課題を{{形式}}で報告する

## 中断して人間に確認する条件
次に該当する場合は実行前に必ず確認を取る。
- 取り消しが困難な操作（削除、初期化、上書き、本番反映、送信、公開、課金）
- 影響範囲が依頼者の外に及ぶ操作（外部送信、共有環境の変更、第三者への通知）
- 権限・認証情報・個人情報の取り扱いが絡む操作
- 指示と現状が矛盾し、どちらを優先すべきか判断できない場合

## 失敗として停止する条件
- 同一の失敗が{{N}}回続いた場合
- 必要な権限・情報が得られない場合
いずれも、途中経過と判明している原因、推奨する次の一手を報告して停止する。
迂回策として安全確認を無効化したり、対象を削除したりしない。
```

## ブロック12: 状態管理と長時間タスク

```
## 進め方
- 着手前に作業計画を{{形式}}で提示し、進捗に応じて更新する
- 一度に全部を終わらせようとせず、検証可能な単位に分けて確実に進める
- 進捗・決定事項・未解決点を{{保存先}}に随時記録する（別セッションから再開できる粒度で）
- 途中で前提が崩れた場合は、作業を続ける前に計画を更新する
```

- 構造化して追う情報（テスト結果、処理件数、タスク状態）は JSON など機械可読な形で保持させる
- 経過メモは自由文でよい
- 複数セッションにまたがる場合、「再開時にまず何を読むか」を明記する

---

## ブロック13: エスカレーションと報告

```
## 報告
- 完了時: 実施したこと / 変更した対象 / 確認した結果 / 残課題 を各3行以内
- 確認が必要なとき: 何を判断してほしいか、選択肢と推奨案、判断しない場合の既定動作
- 失敗時: どこまで進んだか / 何が起きたか / 復旧に必要な操作
自己評価的な表現（「完璧に」「問題なく」）は使わず、確認できた事実だけを書く。
```

---

## マルチエージェント構成

- **各エージェントの責務は1行で言い切れる粒度**にする。曖昧だと担当が重複し、同じ作業を二重に行う
- オーケストレータのプロンプトには「委任先の選び方」「並列化の可否」「結果の統合方法」「サブエージェント失敗時の扱い」を書く
- サブエージェントには**戻り値の形式**を厳密に定義する（親が機械的に統合できる形）
- サブエージェントは呼び出し元の文脈を持たない前提で、タスク記述を自己完結させる
- 共有状態は書き込み競合が起きる。誰が書くかを1つに決める

---

## 評価（エージェントは必ず壊れるので測る）

```
1. 代表タスクを10〜30件、期待される終了状態とセットで用意する
2. 指標: 完了率 / 平均ツール呼び出し回数 / 人間確認の発生率 / 不可逆操作の誤実行 0件
3. プロンプト変更は1度に1箇所。変えたら同じ入力セットで再測定する
4. 失敗ログから「未定義だった条件」を探し、ブロック11に追記する
```
