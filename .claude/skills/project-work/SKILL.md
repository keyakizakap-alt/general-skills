# project-work

依頼: $ARGUMENTS

依頼が空なら、何をするかを1問だけ聞いて止まる。

## 1. 資料確認

- `AGENTS.md` の共通ルールに従う。対象に関係する既存ファイルと `docs/ai/checks.md` の該当する合格条件を読む。
- 対象・完成条件・変更しない範囲を1〜3行で書き出す。不明点が成果を大きく変えるときだけ質問する。

## 2. 計画（軽微なら省略）

- 1ファイル・数行で済む修正は計画を書かずに 3 へ進む。
- それ以外は `tasks/active.md`（無ければ作る。Git追跡外）に、目的・対象・完了条件・手順を短く書く。

## 3. 小さく実行

- 必要な範囲だけ変更する。削除・移動・依存追加・commit / push・公開は、その操作ごとに承認を得てから行う。

## 4. 検査

- `docs/ai/checks.md` から、変更した対象に該当する検査を実行する。実行できないものは「未実行」と理由を記録する。
- 作成者と別の視点が必要な変更（配布スキル本文、マニフェスト、権限設定）は `project-reviewer` に、合格条件・差分（`git diff`）・元資料・検査結果を渡して確認させる。

## 5. 修正

- 失敗や指摘を直して 4 に戻る。
- **停止条件（このプロジェクトの運用上限）**: 同じ失敗が2回続いた、または修正が3巡に達したら、それ以上は直さない。原因の仮説と不足している情報を `tasks/handoff.md` に記録し、利用者に報告して止まる。

## 6. 引き継ぎと報告

- `tasks/active.md` の状態と検証証拠（実行したコマンドと結果）を更新する。中断・持ち越しがあれば `tasks/handoff.md` に、確定事項・変更ファイル・失敗内容・次に行う一手を書く。
- 利用者への報告: 変更ファイル、実行した検査と結果（成功 / 失敗 / 未実行）、未確認事項、依頼外の変更の有無。
