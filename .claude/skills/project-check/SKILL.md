# project-check

検査対象: $ARGUMENTS

対象が空なら、`git status --short` と `git diff --stat` で未コミットの変更を対象にする。変更が無ければそう報告して止まる。

## 手順

1. 対象のファイルを種類に分ける（配布スキル / mod / マニフェスト / エージェント用設定 / その他文書）。
2. `docs/ai/checks.md` から、該当する作業別の合格条件をすべて抜き出す。
3. 各条件を検査する。
   - コマンドで判定できるものは実行し、コマンドと結果（終了コード、要点の出力）を記録する。
   - 読んで判定するものは、根拠となる箇所（`ファイル:行`）を記録する。
   - 実行できない・判定できないものは「未実行」または「未確認」とし、理由を書く。合格条件を緩めない。
4. 必要なら `project-reviewer` に、合格条件・差分・元資料・手順3の結果を渡して独立レビューを依頼する。起動できなければ自分で観点を変えて確認し、「独立レビュー未実施」と記録する。
5. 依頼外の変更（対象と無関係なファイルの差分）が無いかを `git diff --stat` で確認する。

このスキルではファイルを修正しない。公開・送信・購入・commit / push も行わない。

## 報告の形式

```
## 検査結果: <対象>
| 条件 | 結果 | 証拠 |
|---|---|---|
| ... | 成功 / 失敗 / 未実行 / 未確認 | コマンドと結果、または ファイル:行 |

### 失敗・指摘
- <箇所>: <問題> — <理由>

### 未確認事項
- ...

### 依頼外の変更
- なし / <ファイル と理由>
```
