# 0001: エージェント用ハーネスの導入

- 日付: 2026-10-03
- 状態: 採用

## 背景

スキルを追加したときに README・プラグイン定義の記述が更新されず、ずれていた（`plugin.json` の説明が「現在は prompt-architect を収録」のままだった）。
検証の仕組みがなく、エージェントも人間も「完了」を機械的に判断できなかった。

## 決定

1. **完了の定義を `make check`（`tools/check.py`）1本に集約**する。フック・CI・人間が同じものを使う。
2. 指示は `AGENTS.md` に置き、`CLAUDE.md` は `@AGENTS.md` で読み込む。Claude Code 以外のエージェントでも同じ指示を使える。
3. Claude Code フックでループを回す: 編集直後に検証（PostToolUse）、検証が通るまで終わらせない（Stop、差し戻し最大3回）、開始時に進捗を復元（SessionStart）。
4. 進捗は `PROGRESS.md` に書く。チャットの記憶に頼らない。
5. 仕組み自体を `skills/agent-harness-kit` として配布できる形にし、このリポジトリはそれを自分に適用する（`make check` が両者の一致を検証する）。

## 採らなかったもの

- **定期実行（Routine / cron）や PR 自動監視**: 実行環境（クラウドセッション・GitHub 連携）に依存し、どのチャットでも同じように動くとは限らないため、今回は入れない。
- **スキルの eval**: モデルを実際に呼ぶ必要があり、機械的な検証と性質が違うため別途。
- **外部依存（pytest, pre-commit 等）**: 標準ライブラリだけで動くことを優先した。

## 制約・リスク

- フックは `python3` コマンドを前提にする。ない環境では settings.json を `python` に書き換える。
- フックは Claude Code 専用。Codex など他のエージェントでは `AGENTS.md` の「完了の定義」と CI が同じ役割を担う。
- Stop フックは検証が失敗している限り最大3回差し戻す。既存の不具合で失敗する場合は、無関係な作業でも差し戻しが発生する。
